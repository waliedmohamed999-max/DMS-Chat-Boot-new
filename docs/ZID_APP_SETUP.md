# إعداد تطبيق DMS Tech في لوحة شركاء زد

ربط زد مختلف عن سلة. سلة ترسل رموز الوصول في webhook، أما زد فتستخدم **OAuth**:

1. التاجر يضغط "تثبيت" في متجر تطبيقات زد.
2. زد يفتح **رابط التطبيق** عندنا.
3. نحوّله إلى صفحة تفويض زد.
4. بعد الموافقة يعود إلى **رابط إعادة التوجيه** ومعه رمز (code).
5. نستبدل الرمز برموز الوصول، ونُنشئ حساب التاجر أو نربطه بحسابه الحالي.
6. نشترك في أحداث متجره عبر Zid API، ونبدأ سحب بياناته.

فتح التطبيق لاحقاً من لوحة زد يمر بنفس الطريق ويفتح صفحة التطبيق (`/zid/app`) بجلسة جديدة.

استبدل `https://YOUR-DOMAIN` بنطاق المنصة. الروابط جاهزة للنسخ في **لوحة الأدمن ← تطبيق زد**.

## 1. إنشاء التطبيق (partner.zid.sa)

| الحقل | القيمة |
|---|---|
| رابط التطبيق (Application URL) | `https://YOUR-DOMAIN/api/zid/install` |
| روابط إعادة التوجيه (Redirect / Callback URL) | `https://YOUR-DOMAIN/api/zid/oauth/callback` |
| الصلاحيات (Scopes) | قراءة الحساب، الطلبات، العملاء، المنتجات، السلات المتروكة، والويب هوك (قراءة وكتابة) |

## 2. أحداث متجر التطبيقات (Webhooks في صفحة التطبيق)

| الإعداد | القيمة |
|---|---|
| الرابط | `https://YOUR-DOMAIN/api/webhooks/zid/market` |
| الأحداث | `app.market.application.install`، `app.market.application.uninstall`، `app.market.subscription.active`، `.renew`، `.upgrade`، `.warning`، `.suspended`، `.expired`، `.refunded` |
| ترويسة مخصّصة | الاسم `X-DMS-Zid-Token`، والقيمة هي السر المولَّد في لوحة الأدمن (يُعرض مرة واحدة) |

أحداث **المتجر** (الطلبات والعملاء والمنتجات والسلات المتروكة) **لا تُضبط يدوياً**. المنصة تشترك فيها
تلقائياً لكل متجر بعد التثبيت (`POST /v1/managers/webhooks`)، وكل متجر له Basic Auth خاص به.

## 3. المفاتيح، من لوحة الأدمن ← تطبيق زد

| الحقل | المصدر |
|---|---|
| Client ID / Client Secret | لوحة الشركاء ← التطبيق ← مفاتيح API |
| App ID | رقم التطبيق، ويُستخدم كـ `original_id` لاشتراكات الأحداث |
| سر أحداث المتجر | علّم "ولّد سراً جديداً" ثم انسخه إلى الترويسة في القسم 2 |
| ربط الباقات | اسم الباقة في زد ← باقة DMS المقابلة |

بعد الحفظ تسري القيم فوراً. متغيرات `ZID_*` في البيئة احتياط فقط.

## 4. ما يحدث عند التثبيت

- **المتجر مربوط مسبقاً:** تُحدَّث الرموز فقط.
- **مالك حساب DMS بنفس بريد المتجر:** يُربط المتجر بحسابه تلقائياً، ويصله بريد إشعار.
- **لا يوجد حساب:** يُنشأ حساب جديد (بانتظار المراجعة)، ويصل للبريد رابط تحديد كلمة المرور.
- **حساب ببريد مختلف:** التاجر يسجّل دخوله في DMS، ويربط من **التكاملات ← زد ← ربط متجر زد**.

بعد الربط: اشتراك في 12 حدثاً للمتجر، ومزامنة أولى بالخلفية (طلبات، منتجات، عملاء، سلات متروكة).
التاجر يعيد المزامنة من زر **"مزامنة بياناتي الآن"** في صفحة التطبيق، أو من صفحة زد في لوحة DMS.

## 5. التجربة

1. ثبّت التطبيق على متجر تجريبي من لوحة شركاء زد.
2. تأكد أن صفحة التطبيق فتحت وبدأت المزامنة.
3. في **لوحة الأدمن ← تطبيق زد** ستجد المتجر في الجدول، وعبارة "الأحداث مفعّلة".
4. أنشئ طلباً في المتجر التجريبي، وتأكد أنه ظهر في صفحة الطلبات بلوحة DMS.

> بعض تفاصيل Zid API (مسارات قوائم العملاء والسلات وشكل جسم الأحداث) غير موثّقة بالكامل علناً، فالكود
> يقرأها بأكثر من صيغة. لو فشل قسم منها في متجر حقيقي، سيظهر في سجل الخادم ولن يوقف بقية المزامنة.
