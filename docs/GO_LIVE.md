# الإطلاق الحقيقي — إنشاء الحسابات والربط

كل الكود جاهز. هذا الدليل هو ما يبقى: إنشاء الحسابات الخارجية، وضع مفاتيحها في Hostinger، ولصق الروابط في لوحاتها.
بعد كل خطوة افتح **لوحة الأدمن ← جاهزية الربط** (`/admin/setup`) — تعرض ما ينقص، والروابط جاهزة للنسخ، وزر "اختبار الاتصال".

> المتغيرات تُضاف من Hostinger ← Websites ← (الموقع) ← Node.js ← Environment Variables، ثم **إعادة النشر** (Redeploy).
> قاعدة البيانات تُحدَّث تلقائياً أثناء البناء (`prisma migrate deploy` ضمن أمر `build`).

---

## 0) المنصة الأساسية

| المتغير | القيمة |
|---|---|
| `NEXTAUTH_URL` | رابط الموقع النهائي `https://...` (يُبنى عليه كل رابط رجوع وwebhook — اضبطه قبل لصق أي رابط في لوحات المزوّدين) |
| `RUN_WORKER_IN_PROCESS` | لا حاجة له — العامل يعمل داخل الخادم افتراضياً (`0` لتعطيله فقط) |
| `REDIS_URL` | `rediss://...` من Upstash — **خطة Pay as you go** (المجانية 500 ألف طلب/شهر؛ استهلاك المنصة المقاس ~90 ألف/شهر لكن الحملات تزيده، ونفادها يعطّل الطوابير — الدخول نفسه لا يتأثر) |

ثم من **إعدادات المنصة العامة** حوّل وضع التكاملات إلى **Live**.

## 0ب) الذكاء الاصطناعي وعقل البوت
1. لوحة الأدمن ← إعدادات المنصة ← مفتاح OpenAI (يُخزَّن مشفّراً). نموذج المحادثة من نفس الصفحة.
2. نفس المفتاح يشغّل **البحث الدلالي** في عقل البوت (`text-embedding-3-small` — أقل من 0.02$ لكل مليون توكن).
   بدون مفتاح يعمل العقل بالبحث بالكلمات المفتاحية فقط، والإجابات المعتمدة المطابقة تُرسل مباشرة.
3. بعد ضبط المفتاح لأول مرة: كل تاجر أضاف معرفة قبلها يضغط "فهرسة الأسئلة للبحث الذكي"، و"إعادة الفهرسة" على مصادره.
4. التاجر يدرّب البوت من **لوحة التاجر ← عقل البوت**: أسئلة وأجوبة، نصوص، روابط صفحات (HTTPS فقط)، ملفات PDF/نص، واستيراد أسئلة من Excel.

## 1) البريد (SMTP)

| المتغير | القيمة |
|---|---|
| `EMAIL_PROVIDER` | `smtp` |
| `SMTP_HOST` / `SMTP_PORT` | `mail.dmstech.sa` / `465` |
| `SMTP_USER` / `SMTP_PASS` | `info@dmstech.sa` / كلمة مرور الصندوق (أعد تعيينها من cPanel إن ظهر خطأ 535) |
| `EMAIL_FROM` | `DMS Tech <info@dmstech.sa>` |

اختبار: إعدادات المنصة ← "إرسال بريد تجريبي".

## 2) 360dialog — واتساب الرسمي (BSP)

1. سجّل كشريك: https://hub.360dialog.com ← Partner (يتطلب نشاطاً تجارياً موثقاً).
2. من لوحة الشريك:
   - **Partner ID** ← `D360_PARTNER_ID`
   - **API Key** (Partner API) ← `D360_API_KEY`
   - **Webhook secret** ← `D360_WEBHOOK_SECRET`
3. الصق في لوحة الشريك (الروابط في `/admin/setup`):
   - Redirect URL: `https://<الدومين>/api/integrations/d360/callback`
   - Partner Webhook URL: `https://<الدومين>/api/webhooks/d360/partner`
4. أعد النشر ← "اختبار الاتصال" في قسم 360dialog.
5. جرّب بنفسك: سجّل كتاجر ← التكاملات ← "🟢 ربط رقم واتساب" برقم تجريبي.

## 3) Moyasar — شحن المحافظ

1. حساب تاجر: https://dashboard.moyasar.com (ابدأ بمفاتيح الاختبار).
2. Settings ← API Keys ← **Secret key** ← `MOYASAR_SECRET_KEY` (`sk_test_...` ثم `sk_live_...` بعد التفعيل).
3. اختياري: Webhooks ← أضف `https://<الدومين>/api/billing/wallet/moyasar/callback` مع Secret ← `MOYASAR_WEBHOOK_SECRET`.
   (رابط الإشعار يُرسل تلقائياً مع كل فاتورة، فهذه طبقة إضافية فقط.)
4. نفس الحساب يُستخدم لدفع **اشتراكات الباقات**: الترقية/التجديد تحوّل التاجر لصفحة دفع Moyasar ولا تُفعَّل الباقة إلا بعد التحقق من الدفع. بدون المفتاح: الترقية المدفوعة مقفلة برسالة "تواصل مع الفريق".
5. "اختبار الاتصال" ← ثم شحنة تجريبية من محفظة تاجر ببطاقة الاختبار `4111 1111 1111 1111`.

## 4) تسعير الرسائل

لوحة الأدمن ← **تسعير الرسائل**: أدخل أسعار Meta الرسمية للسعودية (SA) لكل من MARKETING / UTILITY / AUTHENTICATION
(بالريال لكل رسالة)، وسعراً افتراضياً `*` للدول الأخرى، وراجع الهامش وأقل مبلغ شحن.
بدون السعر تُرفض رسائل القوالب على 360dialog برسالة واضحة (لا خصم خاطئ).

## 5) سلة

1. أنشئ التطبيق في بوابة شركاء سلة حسب `docs/SALLA_APP_SETUP.md`.
2. لوحة الأدمن ← **تطبيق سلة**: الصق App ID وClient ID وClient Secret وWebhook Secret، ولّد سر الدوال، واربط الباقات — بلا متغيرات Hostinger.
3. الصق الروابط الظاهرة في نفس الصفحة في بوابة سلة (Webhook، الصفحة المضمَّنة، الدوال، الإرسال عبر واتساب).
4. ثبّت التطبيق على متجر تجريبي: تبدأ مزامنة البيانات تلقائياً، والتاجر يعيدها من زر "مزامنة بياناتي الآن" داخل التطبيق في لوحة سلة.

## 5ب) زد

1. أنشئ التطبيق في لوحة شركاء زد حسب `docs/ZID_APP_SETUP.md` (رابط التطبيق ورابط إعادة التوجيه).
2. لوحة الأدمن ← **تطبيق زد**: Client ID وClient Secret وApp ID، ولّد سر أحداث المتجر وضعه كترويسة `X-DMS-Zid-Token`، واربط الباقات.
3. ثبّت التطبيق على متجر تجريبي: يُنشأ/يُربط الحساب، تُفعَّل أحداث المتجر، وتبدأ المزامنة تلقائياً.

## 5ج) الفوترة الإلكترونية — ZATCA المرحلة الثانية
1. الأدمن ← **الفوترة الإلكترونية ZATCA** ← أكمل بيانات البائع (الاسم القانوني، الرقم الضريبي، السجل التجاري، العنوان الوطني).
2. جرّب أولاً ببيئة المطوّرين (OTP: `123345`) — تُجرى 6 فحوص امتثال تلقائياً وتُفعَّل الوحدة.
3. للإنتاج: بوابة fatoora.zatca.gov.sa ← تسجيل وحدة جديدة ← توليد OTP (صالح ساعة) ← اختر "الإنتاج" وأدخله.
4. بعدها كل فاتورة اشتراك مدفوعة بالريال تُوقَّع وتُرسل تلقائياً (كل 5 دقائق أو فوراً بعد الدفع)، وكل استرداد يصدر إشعاراً دائناً.
   التاجر الذي يضيف رقمه الضريبي من صفحة الفوترة يحصل على فاتورة قياسية (اعتماد مسبق).
5. `ZATCA_BASE_URL` اختياري — للاختبار بخادم وهمي فقط.

## 6) نقل التجار القدامى (بعد نجاح 2–4)

لوحة الأدمن ← **نقل التجار لـ 360dialog**:
1. اختر دفعة صغيرة (3–5 تجار) ← "دعوة المحددين" — يصلهم بريد وتظهر لهم بطاقة خطوات في صفحة التكاملات.
2. التاجر يعطّل PIN الرقم في Meta، يربطه عبر 360dialog، ويشحن محفظته. الإرسال ينتقل تلقائياً للقناة الجديدة فور ربطها.
3. بعد جاهزية القناة: "إنهاء النقل" (من التاجر أو منك) يفصل ربط Meta القديم. التاجر يقيّم التجربة.
4. تابع **مراقبة الإرسال** (`/admin/monitoring`): نسبة الفشل، الاستردادات، المحافظ النافدة، أخطاء webhooks — ثم ادعُ الدفعة التالية.
